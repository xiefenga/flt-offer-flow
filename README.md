# Offer Flow

用于逐份生成录用通知书、通过企业 SMTP 发送邮件的本地桌面客户端。界面使用 Electron、React、TSX、LobeHub UI 和 StyleX。

## 本地运行

项目使用 fnm 管理 Node.js 版本。安装并初始化 fnm 后，在项目根目录运行以下命令，fnm 会读取 `.node-version`，按需安装并切换版本。首次启动 Electron 时需要下载对应平台的运行时。

```sh
fnm use --install-if-missing
npm ci
npm run dev
```

开发模式会打开 Electron 窗口。修改 React 组件和 StyleX 样式会在当前窗口热更新；修改 `desktop/`、`shared/` 或 `templates/` 会自动重启 Electron。开发模式使用独立的本地数据目录，按 Ctrl+C 可停止。使用 `npm start` 可构建并运行生产版本。

在「设置 → 邮箱设置」填写企业 SMTP 服务器、端口、加密方式、登录账号、客户端授权码和发件邮箱，保存后可测试连接。TLS 常用 465 端口，STARTTLS 常用 587 端口，具体以邮箱服务商提供的设置为准。

首页的发送记录支持按候选人姓名模糊搜索，可组合筛选公司、部门和发送状态。清空某项筛选即可查看该项的全部记录。

在「设置 → 公司设置」维护公司名称、报到地址、开票信息和限定银行。在「设置 → 部门设置」独立维护部门。填写 Offer 时选择公司和部门，报到地址由所选公司自动带入，只读显示。模板可用 `{{invoiceInfo}}` 和 `{{allowedBanks}}` 引用所选公司的资料。

在「设置 → 邮件模板」编辑主题和富文本正文。将光标放在正文中，点击段落左侧「+」或在段首输入 `/`，搜索并插入变量，右侧会用示例数据实时显示替换后的主题和正文。选中文字后使用「设置链接」添加官网网址，从「+」菜单使用「插入图片」选择 PNG、JPEG 或 GIF 签名图（单张最多 2 MB）。点击正文中的图片后，选择「图片样式」可调整宽度、对齐、圆角与替代文字，高度按比例缩放。图片随模板和待发送记录保存，发送时作为 CID 内嵌图片投递。邮件同时提供带排版的 HTML 和纯文本版本。默认模板保留示例中的开票资料和签名。首次使用时请核对发件主体、资料接收邮箱和签名。在「设置 → 邮箱设置」中输入抄送邮箱，按回车添加为标签，可逐个移除或留空。在「首页」新增 Offer 并保存后，记录进入「待发送」状态，发送时使用邮箱设置中已保存的抄送名单。待发送记录可在表格内编辑或删除。编辑保存时使用当前模板重新生成邮件和 PDF；删除需要二次确认。打开详情可核对正文、预览或导出 PDF，再点击「发送」。“已发送”表示邮件服务器已接受本次提交；“待核实”表示未取得确定结果，重发前应查询邮箱服务商的发送记录。

## 模板变量

在「设置 → 变量管理」中查看预置变量，或新增、改名、删除自定义变量。已被保存的模板引用的变量可改名；删除前需先从模板中移除。邮件主题、邮件正文和附件内容都可以插入变量。

新建和编辑 Offer 时，系统合并两份所选模板引用的自定义变量，每个变量只需填写一次。自定义变量使用必填的单行文本，预览时使用示例值。所选邮件或附件模板的内容、排版发生变化后，可在 Offer 详情中点击「更新邮件和 PDF」。更新后保留发送状态，并在状态记录中登记本次更新。

## 模板与数据

- `templates/fields.json` 定义表单字段、默认值及可引用变量。
- `templates/mail.json` 提供内置邮件模板。用户在界面保存的修改覆盖内置值。
- `templates/notice.json` 保存附件正文。Electron 主进程填充字段、生成 HTML 并使用 Chromium 的 `webContents.printToPDF()` 输出 A4 PDF，并将预览对应的同一份文件作为附件发送。
- SMTP 配置、用户模板和历史记录存放在 Electron 用户数据目录的 SQLite 文件中。授权码经系统凭据加密后保存。每条记录保存生成时的邮件正文、PDF 和状态变更时间。
- 邮件和附件各自支持多份模板。在对应模板页选择已有模板，或用「另存为」保存独立副本。新建或编辑待发送的 Offer 时可分别选择邮件和附件模板。在「设置 → 附件模板」使用富文本编辑器修改整份通知书，可设置标题、文字样式、字号、颜色、列表和段落对齐，也可在光标处插入模板变量。展开 PDF 预览栏顶部的「A4 排版」，可调整字号、行距、段间距及页边距。模板操作栏固定，编辑区和预览区分别滚动。右侧实时预览使用当前未保存的参数和示例数据生成实际 PDF，支持翻页。「预览 PDF」可在系统阅读器中打开。保存后的模板用于新增和再次编辑的 Offer。

## 发送状态

| 当前状态 | 操作或结果                           | 下一状态      |
| -------- | ------------------------------------ | ------------- |
| 待发送   | 从详情确认发送                       | 发送中        |
| 已发送   | 确认再次发送原邮件与 PDF             | 发送中        |
| 发送中   | SMTP 接受邮件                        | 已发送        |
| 发送中   | 明确的连接、认证或投递失败           | 失败          |
| 发送中   | 无法确认投递结果，或应用在发送时退出 | 待核实        |
| 发送中   | SMTP 仅接收部分收件地址              | 待核实        |
| 待核实   | 人工核实邮箱服务商记录               | 已发送 / 失败 |
| 失败     | 在具有附件快照的记录上重新发送       | 发送中        |

已由服务器接收且有邮件和 PDF 快照的记录，可在首页表格或详情中点击「重发」。确认后会向原收件人及当前邮箱设置中的抄送人投递当前保存的邮件和 PDF，使用当前发件账号，原 Offer 的状态随本次发送更新。详情中的「状态记录」保留历次发送过程和结果。

## 验证

```sh
npm test
npm run build
npm run test:desktop
```

单元测试和桌面端测试均使用 TypeScript，由 Node.js 直接运行。运行 `npm run typecheck` 可检查应用和测试代码的类型。

单元测试仅启动 Node.js。桌面端冒烟测试需要图形环境及 openssl，Electron 在后台运行，测试窗口始终隐藏，macOS 下也不会激活应用。它在独立的临时用户目录运行，启动本机 TLS SMTP 服务，验证连接、模板修改、PDF 导出、实际发出的附件内容以及重启后的历史记录。

## 开发工具

React Compiler 通过 Vite 的 React Compiler 预设编译 TSX。运行 `npm run lint` 使用 Oxlint 检查代码，`npm run format` 使用 Oxfmt（Ox Formatter）统一格式，`npm run format:check` 可只检查格式。

## 发布桌面安装包

推送与 `package.json` 版本一致的 `v` 标签后，GitHub Actions 会运行单元测试并构建三个安装包：macOS Apple Silicon 和 Intel 的 DMG，以及 Windows x64 的 EXE。全部成功后，安装包会上传到同一个 GitHub Release。带预发布标识的版本（如 `v0.2.0-beta.1`）会标记为预发布。当前安装包使用默认应用图标，未配置开发者证书签名或 macOS 公证。

例如，发布下一个补丁版本：

```sh
npm version patch
git push origin main --follow-tags
```

本地运行 `npm run package` 可在 `release/` 中生成当前平台的安装包。
